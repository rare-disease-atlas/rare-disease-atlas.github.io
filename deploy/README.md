# Deploying `rare-disease-atlas.github.io` on AWS S3 + CloudFront

This directory contains the zero-backend deployment pipeline for **`https://rare-disease-atlas.github.io`**. Because the primary consumers are **autonomous AI research agents** (`OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`, `Claude-SearchBot`, `Google-Extended`, MCP/OpenAPI clients) alongside viral Hacker News / X human traffic spikes, the hosting configuration prioritizes:

1. **Sub-35ms Global TTFB** via CloudFront edge caching (handles 100k+ concurrent `Show HN` hits for pennies with zero origin scaling failures).
2. **Explicit Agent MIME Types (`text/markdown; charset=utf-8`)** on `/llms.txt`, `/llms-full.txt`, and `.md` files so LLM fetchers never misclassify Markdown as binary or garble UTF-8 symbols (`≥`, `×`, `β`).
3. **Permissive Read-Only CORS (`Access-Control-Allow-Origin: *`)** so browser-based agents, MCP inspectors, and Custom GPT OpenAPI actions can fetch static JSON/YAML feeds directly.
4. **Zero WAF Bot-Blocking False Positives** (ensuring CloudFront never returns `403 Forbidden` or JS challenges to headless AI user-agents).

---

## 1. One-Time AWS Infrastructure Setup

### Step 1.1: Create Private S3 Origin Bucket
Keep the S3 bucket private and serve exclusively through CloudFront Origin Access Control (OAC) over HTTPS:

```bash
export S3_BUCKET="rare-disease-atlas.github.io"
export AWS_REGION="us-east-1"

aws s3api create-bucket \
  --bucket "${S3_BUCKET}" \
  --region "${AWS_REGION}"

aws s3api put-public-access-block \
  --bucket "${S3_BUCKET}" \
  --public-access-block-configuration \
  "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"
```

### Step 1.2: Apply S3 CORS Configuration (Required for Browser/Cloud Agents)
Allows cross-origin `GET` and `HEAD` fetches of `/llms.txt`, `/openapi.yaml`, `/.well-known/*.json`, and `/opportunities.json`:

```bash
cat > /tmp/mf-s3-cors.json << 'EOF'
{
  "CORSRules": [
    {
      "AllowedHeaders": ["*"],
      "AllowedMethods": ["GET", "HEAD"],
      "AllowedOrigins": ["*"],
      "ExposeHeaders": ["Content-Type", "ETag", "Last-Modified"],
      "MaxAgeSeconds": 86400
    }
  ]
}
EOF

aws s3api put-bucket-cors \
  --bucket "${S3_BUCKET}" \
  --cors-configuration file:///tmp/mf-s3-cors.json
```

### Step 1.3: Create CloudFront Response Headers Policy (`CORS` + `llms.txt` Discovery Header)
Creating a managed CloudFront Response Headers Policy guarantees `Access-Control-Allow-Origin: *` on every cached response **and** injects an RFC-8288 HTTP `Link` header (`rel="describedby"`) advertising `/llms.txt` to HTTP-aware agents on every page load:

```bash
cat > /tmp/mf-cf-headers.json << 'EOF'
{
  "Name": "rare-disease-venture-atlas-agent-headers",
  "Comment": "Open CORS + llms.txt Link relation + clean security headers for AI agents",
  "CorsConfig": {
    "AccessControlAllowOrigins": { "Quantity": 1, "Items": ["*"] },
    "AccessControlAllowHeaders": { "Quantity": 1, "Items": ["*"] },
    "AccessControlAllowMethods": { "Quantity": 3, "Items": ["GET", "HEAD", "OPTIONS"] },
    "AccessControlAllowCredentials": false,
    "OriginOverride": true
  },
  "SecurityHeadersConfig": {
    "ContentTypeOptions": { "Override": true },
    "StrictTransportSecurity": {
      "AccessControlMaxAgeSec": 31536000,
      "IncludeSubdomains": true,
      "Override": true
    },
    "ReferrerPolicy": {
      "ReferrerPolicy": "strict-origin-when-cross-origin",
      "Override": true
    }
  },
  "CustomHeadersConfig": {
    "Quantity": 2,
    "Items": [
      {
        "Header": "Link",
        "Value": "</llms.txt>; rel=\"describedby\"; type=\"text/markdown\"",
        "Override": true
      },
      {
        "Header": "X-Robots-Tag",
        "Value": "all, max-snippet:-1, max-image-preview:large",
        "Override": true
      }
    ]
  }
}
EOF

aws cloudfront create-response-headers-policy \
  --response-headers-policy-config file:///tmp/mf-cf-headers.json
```

### Step 1.4: Provision ACM TLS Certificate & CloudFront Distribution
1. Request a public ACM certificate in **`us-east-1`** for `rare-disease-atlas.github.io` and validate via DNS CNAME on `rare-disease-atlas.github.io`.
2. Create a CloudFront distribution pointing to `${S3_BUCKET}.s3.${AWS_REGION}.amazonaws.com` using **Origin Access Control (OAC)**:
   - **Default Root Object:** `index.html`
   - **Viewer Protocol Policy:** `Redirect HTTP to HTTPS`
   - **Compress Objects Automatically:** `Yes` (Brotli + Gzip)
   - **Cache Policy:** `Managed-CachingOptimized` (or forward `Origin` header if testing CORS variation)
   - **Response Headers Policy:** Attach `rare-disease-venture-atlas-agent-headers` created above.
3. Grant CloudFront OAC read access (`s3:GetObject`) on `arn:aws:s3:::rare-disease-atlas.github.io/*` via the S3 bucket policy generated by CloudFront, and point `rare-disease-atlas.github.io` DNS (`A`/`AAAA` ALIAS or `CNAME`) to your `d111111abcdef8.cloudfront.net` domain.

> **CRITICAL AI CRAWLER WARNING (AWS WAF / Bot Control):**  
> Do **NOT** enable AWS WAF `AWSManagedRulesBotControlRuleSet` or JS-challenge rate limiters on this distribution. Headless AI search indexers (`OAI-SearchBot`, `Claude-SearchBot`, `PerplexityBot`) and live user-triggered agent fetchers (`ChatGPT-User`, `Claude-User`, `Perplexity-User`) do not execute JavaScript challenges and will drop `rare-disease-atlas.github.io` from citations if challenged. Static S3 + CloudFront handles bot traffic natively at near-zero cost.

## 2. Deploying Site Updates

Test with `--dry-run` first:

```bash
chmod +x ./deploy/deploy-s3.sh
S3_BUCKET=rare-disease-atlas.github.io ./deploy/deploy-s3.sh --dry-run
```

Deploy live and invalidate CloudFront edge caches:

```bash
S3_BUCKET=rare-disease-atlas.github.io \
CLOUDFRONT_DISTRIBUTION_ID=E1234567890ABC \
./deploy/deploy-s3.sh
```

## 3. Post-Deploy Verification Checklist

Run these three commands immediately after deployment to confirm exact headers for both humans and AI agents:

```bash
# 1. Verify HTML + Link rel="describedby" header + sub-50ms cache hit
curl -sI https://rare-disease-atlas.github.io/ | grep -iE "http/|content-type|link|access-control|x-cache"

# 2. Verify llms.txt serves as text/markdown; charset=utf-8 (NOT binary/octet-stream)
curl -sI https://rare-disease-atlas.github.io/llms.txt | grep -iE "http/|content-type|access-control"

# 3. Simulate OpenAI SearchBot & PerplexityBot fetches
curl -sI -A "Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko); compatible; OAI-SearchBot/1.0; +https://openai.com/searchbot" \
  https://rare-disease-atlas.github.io/rare-disease-business-models.html | head -n 10
```
